# 拼多多自建前端可行性（2026-11-23）

**结论：不自建完整商城；保留官方 H5，继续做容器内的通用性能优化。** 自建只能作为将来拿到正式授权、稳定商品与交易接口后的独立项目，不应作为本次卡顿的解法。

| 问题 | 判断 |
|---|---|
| 数据从哪来 | 现有 `PddH5Connector` 与 WebView 嗅探只覆盖订单、物流、取件信息，**不能复用为商城数据源**。目录、搜索、详情、规格库存、购物车、价格促销、下单、支付、售后均需要另一套接口。复制 H5 私有接口虽在技术上可行，但签名、风控、字段和页面改版会形成长期逆向维护。 |
| 合规与账号风险 | 使用用户会话抓取非公开商城接口，可能违反平台服务约定，且会把账号风控暴露给整个购物流程；价格、库存、支付状态一旦错配就是交易正确性问题。不得通过绕过签名、验证码或设备风控来支撑自建。 |
| 官方 H5 / 小程序 / 联盟 | 官方 H5 是当前成本最低且交易闭环完整的方案；小程序通常要求宿主运行环境与平台接入，不能直接嵌入 Flutter WebView。拼多多开放平台有多多进宝推广类接口，可用于获授权后的商品检索/推广链接，但不是用户商城的完整目录、购物车、收银台和售后接口。应以正式接口权限审核结果为准，不能把「能查推广商品」等同「能重建商城」。 |
| 工作量与维护 | 仅授权商品浏览（搜索、列表、详情、深链回官方 H5 下单）粗估 4–8 人周；完整交易商城至少数月并需持续跟进接口、促销、支付与合规。相对地，本次 WebView 清理脚本优化只改容器，不复制平台业务。 |
| 可做局部 | 若未来确有原生浏览需求，先做「多多进宝授权商品浏览 + 官方 H5 交易」，明确展示价格更新时间与跳转关系；在正式权限、服务端签名保管和风控合规落地前不立项。 |

官方入口（访问日期 2026-11-23）：[拼多多开放平台](https://open.pinduoduo.com/)、[多多进宝](https://jinbao.pinduoduo.com/)。
