# 合成样本约定

仓库是公开的。进入 git 的物流样例必须是可辨识的合成数据，不能是真实运单、取件码、收件人、电话或具体住址。

## 真实样本放哪里

未脱敏的原始日志、采集导出、真机截图和完整轨迹只放在已被 `.gitignore` 忽略的目录：

- `private/`
- `test/fixtures_private/`
- `real_world/`

这些目录如果还不存在，需要时再在本地创建即可，不要提交。

## 合成数据怎么写

优先使用门禁能直接识别的严格演示形态，避免再扩大允许名单：

- 运单号用长零填充或整段连续数字，例如 `YT0000000000001`、`JT0000000000001`、`YT0012345678901`（整段连续可含 9→0 循环，但必须覆盖去掉前导零后的全部数字，不能只靠局部窗口）
- 取件码优先用项目演示码 `3-2-1002`，或全同数字 `9-9-9999`、整段连续 `12-3-4567`、极短占位 `8-2-6`
- 地点用「示例市」「示例南转运中心」「青柠花园」这类明显虚构名称
- 手机号不要在测试里写连在一起的 11 位真号形态；占位请继续用相邻字符串（如 `'138' '00001111'`）或 `1**********`

「不同数字比较少」或「中间有一段连续数字」不能当作合成证明。如果某个合成标记形态上像真值，又必须保留，把它完整登记到 `tools/pii_allowlist.txt`，并在测试或注释里写明是自造/示例。不要为了过检批量写入新的真实形态样例。

## 提交前检查

```bash
bash tools/check_no_pii.sh
bash tools/test_check_no_pii.sh
```

门禁默认扫描 `test/`、`docs/`、`lib/` 以及根目录说明文档，覆盖运单号、取件码和手机号。命中时只报告路径、行号和规则名，不打印原文。已忽略的真实样本目录不会被扫描。

## 已知剩余边界

- 两端都是 1–12、年末段为 19xx/20xx 的标记（如 `11-4-2015`）既可能是日期也可能是取件码，门禁仍按取件码处理；只有其中一组为 13–31 的日期（如 `11-16-2026`）才会被排除。
- 未列入的承运商前缀、无字母前缀的纯数字长单号，默认不扫。
- 全角点、括号等其他分隔的手机号可能仍漏检。
- 地名和身份描述不在门禁范围内。
- `tools/` 不在默认扫描根里（夹具目录默认排除，显式传入仍可测）。

本约定只约束后续提交。清理历史提交需要单独授权，不能靠再提交覆盖来抹掉旧记录。
